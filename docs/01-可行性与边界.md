# 可行性与边界

结论：**三件事都做得到，但各有一处硬边界**。下面按设备拆开讲，并给出绕不过去时怎么办。

---

## 1. Spark Mini（Positive Grid）

**可行。** Spark 通过蓝牙与手机通信时使用两条独立链路：

- 音频：经典蓝牙 A2DP（当音箱用）；
- 控制：**BLE**，官方帮助页称为 "Tone Control (BLE)"，只能在 Spark App 内完成配对。

BLE 的 GATT 结构已被公开逆向：服务 `FFC0`，写特征 `FFC1`，通知特征 `FFC2`；广播名形如 `Spark MINI BLE`。协议本体是「块 + 分块 + 7bit 打包 + 异或校验」的 msgpack 变体，社区文档与实现都很完整：

- [paulhamsh/SparkIO4](https://github.com/paulhamsh/SparkIO4)：可直接对照的字节构造代码；
- [Spark-Bluetooth-Message-Format](https://github.com/paulhamsh/Spark-Bluetooth-Message-Format)：协议说明 v3.2（含分块、校验、预设结构）。

因此本 App 能做到：读回当前音色的名称、7 个模块（噪声门/压缩/过载/音箱/调制/延迟/混响）的开关与每个参数、切预设、单参数修改、Tap Tempo。

**边界与风险**

1. 公开资料以 Spark 40 为主。Mini 的差异在于：接收方向**不需要 16 字节块头**、BLE 单包 20 字节。代码里做了自动识别与 20 字节切片，但仍需实机确认。
2. 音箱→App 的数据「可能不可靠」（协议文档原话）。代码对校验错误采取“记日志但继续解析”，并做了分块重组。
3. **整包写预设未实现**：当前只发单参数/单开关命令，足够演出用；整包写入需要额外的预设校验和逻辑，后续可加。
4. 部分命令字（如 Tap Tempo 的 `0x0163`）在公开代码里只有接收端，没有发送端，属于**待实机验证**项。

## 2. Hotone Pulze Mini

**部分可行，且边界是厂商画的。** Pulze 支持 Bluetooth 5.0 双模，明确写了 **Bluetooth MIDI**，并发布了官方的
[Pulze MIDI Control Information List（Firmware V1.0.6）](https://res.hotoneaudio.com/prod/support/Pulze%20MIDI%20Control%20Information%20List%20Firmware%20V1.0.6.1701218099204.pdf)。

官方开放的 CC 只有这些（完整表见[协议笔记](03-协议笔记.md)）：

| 能力 | CC |
|---|---|
| 换音色 | 26 上一个 / 27 下一个（PC 也可，见备注） |
| 块开关 | 45 NR、46 PRE、47 AMP、48 CAB、49 EQ、50 Fx1、51 Fx2 |
| 音量 | 7 音色、8 乐器、9 蓝牙、10 辅助输入 |
| 调音表 | 55 |
| 速度 | 74/75 设定、76 Tap Tempo |
| 鼓机 | 60–67 |

**关键限制：没有任何“单个效果参数”的 CC。** 也就是说，用官方 MIDI 能切块、能调音量、能换音色，但**不能改混响时间、延迟反馈这类数值**。

三条路：

1. 接受限制：App 只做开关 + 音量 + 换音色（当前实现）。
2. 演出前用官方 Pulze Editor 把音色调好，App 只负责切换。
3. 逆向 Pulze Editor 的私有 BLE 协议（不是 MIDI），拿到参数写命令。工具链已备（`tools/ble_probe.py`），但需要真机抓包，工作量和固件相关性都较高。

> 备注：Pulze 是否用 Program Change 选音色，官方表里没写；代码默认按 `PC = 音色号` 发送，若不生效就改用 CC26/27 步进。

## 3. KORG Module Pro

**能控制，但只能“选音色”，不能“读状态”。**

- Korg 官方支持文档明确：Module 支持 Program Change，**编号对应 Set List 里的排列顺序**（[Are program changes supported?](https://support.korguser.net/hc/en-us/articles/203456004-Are-program-changes-supported)）。所以 App 的音色表第 n 项 = 发 PC n。
- Module 没有对外广播“当前音色名”的机制，也没有参数回读。因此 App 的“大字音色名”来自**你自己维护的槽位表**；发 PC 与显示名字是同一动作的两半。
- Module 支持 Background Audio，可以后台持续运行并接收 MIDI。

**唯一投递路径（同一台 iPhone）**

本 App 创建系统级虚拟 MIDI 端口 `GuitarHub`，Module 在后台（打开 Background Audio）把 MIDI 输入选成它。
CoreMIDI 的虚拟端口是系统级的，前台 App 向后台 App 投递 MIDI 属于标准用法。

**如果这条路走不通**（例如 Module 的 MIDI 输入列表里只有硬件端口、没有虚拟端口）：

- 不做第二台设备、不做 Wi-Fi 桥接；
- 本 App 继续负责：音箱音色显示/模块开关/参数、蓝牙踏板、节目单；
- Module 仍然在后台放音，但换音色改成手动——它本来就是“调节不方便”，这也是本项目的出发点。

**边界**

- 只发不收：换了音色、改了参数，App 不知道。演出流程必须“以 App 为唯一入口”切音色。
- 纯 MIDI 控制无法操作 Module 的界面；它没有暴露参数 CC（官方只保证 PC 与 Set List 导航）。
- 是否接受虚拟端口，取决于 Module 当前版本；上机第一件事就是看它的 MIDI 输入列表有没有 `GuitarHub`。

## 4. iOS 平台约束

- **多路 BLE 并发**：CoreBluetooth 可同时连多台外设，实际稳定值约 6–7 台；本项目只用 2 台（音箱 + 踏板），余量充足。
- **后台 BLE**：`bluetooth-central` 后台模式可让连接在锁屏/切后台后维持；踏板的踩钉事件仍能到达。
- **虚拟 MIDI 跨 App**：CoreMIDI 的虚拟端口是系统级的，前台 App 可向后台 App 投递；这也是同机方案的依据。
- **安装**：不上架就只能自签。免费 Apple ID 7 天过期、最多 3 个 App；付费开发者账号 1 年。详见[构建与安装](04-构建与安装.md)。

## 5. 合规提醒

逆向协议用于**个人设备的互操作性**在多数司法辖区属于合理使用范畴，但仍可能违反厂商的使用条款（尤其固件升级后失效）。本仓库不分发任何厂商代码或音色资源，仅包含自行编写的协议实现与配置。请勿用于商业分发。
