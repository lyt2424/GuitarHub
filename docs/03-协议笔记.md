## 1. Spark（BLE 私有协议）

### 1.1 连接

| 项 | 值 |
|---|---|
| 服务 | `FFC0` |
| App → 音箱（写） | `FFC1` |
| 音箱 → App（通知） | `FFC2` |
| 广播名 | `Spark MINI BLE` / `Spark 40 BLE` / `Spark GO BLE` |
| 音频 | 另一条经典蓝牙 A2DP，与控制无关 |

Spark 40 在数据块前有 16 字节块头（`01 FE` 开头），Mini/GO 没有。代码遇到 `01 FE` 会自动跳过，兼容两者。

### 1.2 分块格式

```
F0 01 <seq> <xor> <cmd> <sub> <7bit 打包的 payload> F7
```

- `seq`：分块序号（同一条消息的各块相同）。
- `xor`：payload **打包后**所有字节的异或。
- payload 打包规则：每 8 字节为一组，第 1 字节是**位掩码**，其后 7 字节只保留低 7 位；
  掩码第 k 位为 1 表示该组第 k 个字节的真实值要 `| 0x80`。

官方代码里的实例（读取预设的其中一个分块）：

```
F0 01 04 1F 03 01  20  0E 00 19 00 00 59 24  00 39 44 32 46 32 41 41
                    00 33 2D 34 45 43 35 2D  00 34 42 44 37 2D 41 33  F7
```

解包后：`0E 00 19 | 00 00 D9 24 39 44 …`，前 3 字节是分块头（总块数 14、本块序号 0、数据长 25），
`D9 24` 是 msgpack 的“36 字节长字符串”，后面是预设 UUID 的 ASCII。

预设消息（`0x0101` / `0x0301`）每 32 字节重置一次分组，其它消息每 8 字节连续分组。

### 1.3 命令表

方向以 **App → 音箱** 为准（`cmd=0x01`）：

| cmdsub | 含义 | payload |
|---|---|---|
| `0x0115` | 模块开/关 | 前缀字符串(模块名) + `C3`(开) / `C2`(关) |
| `0x0104` | 改一个参数 | 前缀字符串(模块名) + 参数号 + `CA` + 4 字节浮点(0…1) |
| `0x0138` | 切硬件预设 | 当前预设号 + 目标预设号（0–3） |
| `0x0106` | 换效果型号 | 前缀字符串(旧名) + 前缀字符串(新名) |
| `0x0163` | Tap Tempo | 无（**待实机验证**） |

请求（`cmd=0x02`）：

| cmdsub | 含义 | payload |
|---|---|---|
| `0x0201` | 读预设 | 预设号高/低字节 + 30 个 `00`；`01 00` 表示“当前音色” |
| `0x0210` | 读当前硬件预设号 | 无 |
| `0x0211` | 读音箱名 | 无 |
| `0x0223` | 读序列号 | 无 |
| `0x022f` | 读固件版本 | 无 |

音箱 → App（`cmd=0x03`，部分也会以 `0x01` 回显）：

| cmdsub | 含义 |
|---|---|
| `0x0301` / `0x0101` | 完整预设（分块传输） |
| `0x0311` | 音箱名 |
| `0x0310` | 当前硬件预设号 |
| `0x0315` / `0x0115` | 模块开关变化 |
| `0x0337` / `0x0104` | 参数变化 |
| `0x0338` / `0x0138` | 预设被切换 |
| `0x0363` | Tap Tempo / BPM |

> 命令字来自 SparkIO4 的 `MessageOut`（基址 `0x0100`）。若某固件不响应，优先怀疑这里是 `0x0100` 还是 `0x0101` 基址。

### 1.4 预设 payload（msgpack 变体）

顺序固定：

```
currentPreset(u8) presetNumber(u8)
uuid(str) name(str) version(str) description(str) icon(str)
bpm(float)
0x90+7             ← 7 个模块
  for each: 模块名(str) onoff(C3/C2) 0x90+参数个数
            for each: 参数序号(u8) 0x91 float(0…1)
checksum(u8)       ← 预设校验和
```

- 字符串：`0xA0+len` + ASCII；长串用 `0xD9 len`；部分字段前面多一个 `0x00`。
- 浮点：`0xCA` + 4 字节，**大端**（代码里做了越界回退到小端的兜底）。
- 模块槽位：`0` 噪声门、`1` 压缩、`2` 过载、`3` 音箱、`4` 调制、`5` 延迟、`6` 混响。
- 参数个数随型号变化（音箱 5 个、混响 7 个…），所以 UI 只显示设备实际传上来的参数。

`tools/spark_frame_test.py` 用纯 Python 复刻了打包/解包，并覆盖了高位掩码、分块头、随机负载，可先跑它验证算法。

## 2. Hotone Pulze（官方 BLE MIDI）

Pulze 支持 Bluetooth 5.0 双模，控制走 **BLE MIDI**（服务 `03B80E5A-…`），不需要私有协议。

官方 MIDI Control Information List（Firmware V1.0.6）全文要点：

| CC | 值域 | 含义 |
|---|---|---|
| 7 | 0–100 | 音色音量 |
| 8 | 0–100 | 乐器音量 |
| 9 | 0–100 | 蓝牙音量 |
| 10 | 0–100 | 辅助输入音量 |
| 26 | 0–127 | 上一个音色 |
| 27 | 0–127 | 下一个音色 |
| 28 | 0–2 | 主界面：0 演奏 / 1 歌单 / 2 自定义面板 |
| 45 | 0–127 | NR 开关（0–63 关，64–127 开） |
| 46 | 0–127 | PRE 开关 |
| 47 | 0–127 | AMP 开关 |
| 48 | 0–127 | CAB 开关 |
| 49 | 0–127 | EQ 开关 |
| 50 | 0–127 | Fx1 开关 |
| 51 | 0–127 | Fx2 开关 |
| 55 | 0–127 | 调音表开关 |
| 60 | 0–127 | 鼓机菜单开关 |
| 61 | 0–127 | 鼓机播放/停止 |
| 62 | 0–2 | 鼓机速度 MSB |
| 63 | 0–127 | 鼓机速度 LSB（40–300 BPM） |
| 64 | 0–127 | 鼓机 Tap Tempo |

## 3. KORG Module（Program Change）

- 官方支持文档：Module 响应 Program Change，**编号按 Set List 的排列顺序**。
- 因此 App 的槽位表就是 Set List 的镜像：第 n 项 ↔ PC n（0 起算；若你的 Module 从 1 起算，把槽位整体 +1）。
- Module 没有 MIDI 回传状态：换音色后它不会告诉你“我现在是哪个”，所以显示名只能由 App 维护。
- 后台音频打开后，Module 可在后台持续运行并接收 MIDI。

## 4. BLE MIDI 包格式

```
<header 1xxxxxxx> <timestamp low 0xxxxxxx> <MIDI 字节…> [<header> <ts> <bytes>…]
```

- 所有最高位为 1 的字节是包/时间戳头，跳过即可得到纯 MIDI 流。
- 发送时时间戳取当前毫秒的低 13 位；接收端按 running status 解析（`MIDIStreamParser`）。
- 本项目让踏板**直连 App**，而不是在系统设置里配 BLE MIDI，原因：
  系统级 BLE MIDI 会把同一条踩钉同时送给所有 App（包括 Module），造成重复触发；
  直连后由 `PedalRouter` 决定这一脚是给音箱还是给 Module。
