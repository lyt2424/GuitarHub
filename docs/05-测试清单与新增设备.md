# 实机测试清单与新增设备

第一次上真机时按顺序做，每步记下结果。协议类问题基本都能在这一页定位。

## A. 编译与启动

- [ ] `xcodegen generate` 无报错
- [ ] 真机编译通过（模拟器没有蓝牙，无法测设备）
- [ ] 启动后五个页签都能打开，不闪退
- [ ] 设置页能看到 `Spark Mini`、`Pulze Mini` 两份设备配置

## B. 入口与连接

- [ ] 启动页两个大按钮：**电吉他模式** / **键盘模式**
- [ ] 电吉他模式标题栏的音箱图标里能切换 Spark / Pulze（以后新增设备也会出现在这里）
- [ ] 切换设备时，上一台自动断开，踏板组跟着换成同名那一组
- [ ] 颜色块：开启时是彩色，关闭变灰；点方块切换开关，点右上角小图标调参数
- [ ] 设备页点“搜索”，能出现你的 Spark（名字含 `Spark MINI`）
- [ ] 连接后状态变“已连接”，`GATT` 区域能看到 `FFC0 → FFC1[w|wn], FFC2[n]`
- [ ] 断开后点“重连上次”能恢复

## C. Spark 读回音色

- [ ] 连上后自动出现音色名（与音箱屏幕/官方 App 一致）
- [ ] 7 个模块的 ON/OFF 与音箱实际一致
- [ ] 扭一下音箱上的旋钮，App 里对应参数跟着变
- [ ] 在音箱上切预设，App 的音色名与编号跟着变

如果 C 失败：

1. 看“原始收发”有没有 `F0 01 …` 回包；
2. 有回包但解析乱 → 看日志里“预设解析失败”；多半是浮点字节序，改 `SparkPayloadReader.float` 的 fallback；
3. 没回包 → 请求命令字不对，试 `0x0201` 的预设号用 `00 00`（预设 0）而不是 `01 00`。

## D. Spark 写参数

- [ ] 拖动“混响 → 强度”，音箱上的混响量实时变化
- [ ] 关掉混响，音箱上混响灯灭
- [ ] 改完再点“读取”，值不跳回去（说明写入生效）

## E. 预设切换

- [ ] 演出页“下一音色”，音箱切到下一个硬件预设，App 名称同步
- [ ] 踏板 CC22/CC23 也能切

## F. 蓝牙踏板

- [ ] 踏板页能搜到踏板并连接
- [ ] 踩 CC20 → 混响开关翻转；同时“实时监视”出现一行记录
- [ ] 表情踏板（CC12）→ 混响强度连续变化
- [ ] 切到 B 组后再踩，行为按 B 组映射
- [ ] 锁屏后踩钉仍然有效（后台 BLE）

## G. KORG 同机（可选，能通最好）

- [ ] Module 打开 Background Audio，MIDI 输入列表里能看到 `GuitarHub`
- [ ] 选中后，App 点“下一音色”，Module 切到 Set List 的下一项
- [ ] 切到别的 App 再回来，PC 仍能发（虚拟端口还在）
- [ ] 踏板映射 `.korgStep` 生效

**如果 G 不成立**（列表里没有 `GuitarHub`）：不做任何补救，跳过。
本 App 的音箱/踏板/节目单功能与 Module 完全解耦；Module 照常后台放音、手动换音色。

## H. 现场演练

- [ ] 飞行模式 + 只开蓝牙，整套流程可用（Wi-Fi 关闭时双机方案不可用，需注意）
- [ ] 连续踩 50 次无漏触发、无卡顿
- [ ] 电量消耗可接受（BLE + 后台音频）

# 新增设备

## 1. 先判断属于哪一类

| 设备类型 | 做法 | 工作量 |
|---|---|---|
| 支持 BLE MIDI 且官方有 MIDI 实现表 | 复制 `pulze-mini.json`，改 CC 号 | 10 分钟 |
| 私有 BLE 协议，但命令简单 | 抓包后用 `template` 思路（见下） | 半天 |
| 私有 BLE 协议，且有状态回读（像 Spark） | 写一个新的 `DeviceCodec` | 1–2 天 |

## 2. 写一份 profile

最小可用示例（任何“收到 CC 就开关模块”的设备）：

```json
{
  "id": "my-pedal",
  "name": "My Pedal",
  "transport": { "kind": "bleMIDI", "codec": "midiCC", "namePrefixes": ["MyPedal"] },
  "capabilities": { "presetCount": 32 },
  "modules": [
    { "id": "reverb", "name": "混响",
      "bypass": { "kind": "cc", "cc": 45, "onValue": 127, "offValue": 0 } },
    { "id": "volume", "name": "音量", "isGlobal": true,
      "params": [ { "id": 0, "name": "音量", "mapping": { "kind": "cc", "cc": 7 } } ] }
  ]
}
```

字段含义见 `docs/02-架构与数据流.md`；所有字段都可省略，缺省会落默认值。

## 3. 装进 App（不用重编译）

把 JSON 放进「文件」App 的
`我的 iPhone/吉他中枢/Profiles/`（App 已开启文件共享），然后在 App 的 设置 → 设备配置 → **重新加载设备配置**。
同名 `id` 的用户配置会覆盖内置配置，所以也可以用这招微调内置设备而不必重编译。
加载失败会直接显示原因（缺 id、模块 id 重复、cc 缺失等）。

## 4. 抓包工具

```bash
pip install bleak
python tools/ble_probe.py scan
python tools/ble_probe.py dump --name "MyPedal"                # 列出 GATT
python tools/ble_probe.py watch --name "MyPedal" --seconds 30  # 打印通知字节
python tools/ble_probe.py write --name "MyPedal" --char FFC1 --hex "01FE00..."
```

操作顺序建议：先 `watch` 看设备主动上报什么，再在官方 App 里做一个动作同时抓包，
把“变的那几个字节”对应到功能。抓到稳定命令后，再决定是写 profile 还是加 codec。

## 5. 路线图（按优先级）

1. Spark 整包预设写入（`0x0101`）+ 保存到硬件预设（`0x0127`）
2. `template` 编解码器：把“命令模板 + 变量”写进 JSON，实现零代码适配简单私有协议
3. Pulze Editor 私有协议逆向（参数级编辑）
4. 预设库导出/导入（换手机不丢数据）
